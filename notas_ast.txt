### Passo a Passo para Construir uma AST (Árvore de Sintaxe Abstrata)

---

#### **1. Compreenda o Objetivo da AST**
A **AST** é uma representação hierárquica da estrutura de uma linguagem ou consulta (no seu caso, SQL). Ela organiza as informações de maneira clara para facilitar o processamento e a execução das operações. Por exemplo:
- Query: `SELECT * FROM USERS WHERE NAME = 'Felipe';`
- Representação:
  ```plaintext
  Query
  ├── Tipo: SELECT
  ├── Colunas: ["*"]
  ├── Tabela: "USERS"
  └── Condição:
      ├── Coluna: "NAME"
      ├── Operador: "="
      └── Valor: "Felipe"
  ```

---

#### **2. Entenda os Componentes do SQL**
Antes de construir a AST, liste os componentes básicos que a sua linguagem ou query pode ter:
- **SELECT**: Quais colunas serão selecionadas?
- **FROM**: De qual tabela?
- **WHERE**: Há condições para filtrar os dados?
- **INSERT**: Em qual tabela? Quais colunas e valores?

Decida quais funcionalidades você quer implementar inicialmente. Focar no básico ajuda a progredir sem se perder em complexidade.

---

#### **3. Estruture o Design da AST**
Pense na hierarquia de dados. Cada query terá:
1. Um tipo principal (`SELECT`, `INSERT`, etc.).
2. Subcomponentes dependentes:
   - **Para SELECT**:
     - Lista de colunas.
     - Nome da tabela.
     - Condição (opcional).
   - **Para INSERT**:
     - Nome da tabela.
     - Colunas-alvo.
     - Valores correspondentes.

Desenhe no papel a relação entre esses elementos, como se fosse um organograma.

---

#### **4. Defina a Estrutura Hierárquica**
Converta a hierarquia em uma ideia estruturada. Por exemplo:
- O nó raiz é a query inteira.
- Os filhos diretos são os componentes principais (`SELECT`, `FROM`, `WHERE`).
- Subnós são os detalhes de cada componente (e.g., colunas selecionadas, tabela, condições).

Isso ajuda a visualizar o que cada nó deve conter e como os componentes se conectam.

---

#### **5. Tokenize a Entrada**
Antes de construir a AST, você precisa transformar a query em **tokens**:
- Cada palavra-chave, nome, operador ou símbolo vira um token.
- Exemplo: `SELECT * FROM USERS WHERE NAME = 'Felipe';` →  
  ```
  [
    KEYWORD: SELECT,
    STRING: *,
    KEYWORD: FROM,
    IDENTIFIER: USERS,
    KEYWORD: WHERE,
    IDENTIFIER: NAME,
    SYMBOL: =,
    STRING: 'Felipe',
    SYMBOL: ;
  ]
  ```
Esses tokens serão a base para criar a AST.

---

#### **6. Parseie os Tokens**
Com os tokens prontos, percorra-os para identificar a estrutura da query e preencher a AST:
1. **Identifique o Tipo de Query**
   - O primeiro token geralmente indica o tipo (`SELECT`, `INSERT`, etc.).
   - Isso determina a estrutura básica da AST.

2. **Preencha os Subcomponentes**
   - Se for um `SELECT`:
     - Após `SELECT`, pegue as colunas.
     - Após `FROM`, identifique a tabela.
     - Se houver `WHERE`, extraia as condições.
   - Se for um `INSERT`:
     - Após `INSERT INTO`, identifique a tabela.
     - Extraia as colunas (opcional) e valores.

3. **Trate Erros**
   - Se encontrar tokens fora do esperado, registre um erro.
   - Isso garante que apenas queries válidas sejam representadas na AST.

---

#### **7. Organize os Dados na AST**
A partir dos tokens, crie nós na árvore para representar cada parte da query:
- Cada componente principal (e.g., `SELECT`, `FROM`) vira um nó.
- Subcomponentes (e.g., colunas, condições) se tornam filhos desses nós.
- Certifique-se de que todos os dados relevantes da query estão na árvore.

---

#### **8. Teste e Valide a AST**
Para cada query:
1. Verifique se a AST gerada reflete a estrutura esperada.
2. Compare com um exemplo manual (desenhado no papel ou em um diagrama).
3. Teste queries com diferentes combinações de componentes para validar robustez.

---

#### **9. Caminhe pela AST**
Depois de construída, a AST será usada para executar ou transformar a query:
- **Caminhar na AST** significa percorrer os nós para:
  - Interpretar o que a query faz.
  - Validar se a query é lógica (e.g., checar se as tabelas e colunas existem).
  - Gerar instruções para o banco de dados executar.

Para isso, use um método que percorra a árvore recursivamente, começando pelo nó raiz (a query).

---

#### **10. Expanda Gradualmente**
Quando o básico funcionar, adicione mais funcionalidades:
- **Suporte a outros tipos de queries**: `INSERT`, `UPDATE`, `DELETE`.
- **Expansão das condições**: Suporte a `AND`, `OR`, parênteses, etc.
- **Funções e expressões**: Suporte para agregações (`COUNT`, `SUM`) e operações.

---

#### **Resumo do Processo**
1. Compreenda a estrutura lógica da query.
2. Liste os componentes necessários.
3. Transforme a entrada em tokens.
4. Crie uma AST hierárquica baseada nos tokens.
5. Valide a AST gerada com exemplos.
6. Caminhe pela AST para executar ou interpretar a query.
7. Expanda gradualmente para novos casos.

Se precisar de mais explicações ou exemplos sobre algum passo específico, posso detalhar!
